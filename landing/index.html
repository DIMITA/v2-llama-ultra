architecture

How it works

Four stages. One ultra-optimized inference pipeline.

01

Hardware Detection

LLaMA Ultra scans your CPU cores, free RAM, and GPU VRAM to build a hardware profile. This happens in milliseconds and is fully automatic.

Profile: medium
RAM: 6.2 GB free
GPU: none
→ INT8, 256MB chunks
02

Adaptive Quantization

The model is compressed on the fly using the best quantization level for your hardware. Edge transformer layers keep higher precision.

LLaMA 7B FP32 → 26 GB
→ INT8 quantized  → 6.7 GB
→ Reduction: 3.9×
03

Intelligent Chunking

The model is split into 256MB chunks. Only the layers needed for the current inference step are in RAM at any time. Chunks are evicted when not needed.

32 layers → 8 chunks (256MB ea.)
Cache: [■■■□□□□□]
RAM: 768 MB / 2048 MB
04

Streaming Inference

Tokens stream out as soon as they're generated. Back-pressure and adaptive throttling prevent RAM spikes. Works over SSE, WebSocket, or stdio.

     the full explanation...
     [128 tokens · 14.2 t/s]

// Install: npm install v2-llama-ultra
const { createClient } = require('v2-llama-ultra');

// Auto-detects your hardware, picks best settings
const client = await createClient({
  modelsDir:    './models',
  quantization: 'auto',   // or 'int4' | 'int8' | 'fp16'
});

await client.load('llama-3-7b.gguf');

const text = await client.generate(
  'Explain quantum computing in 3 sentences'
);

console.log(text);
const { createClient } = require('v2-llama-ultra');

const client = await createClient();
await client.load('llama-3-7b.gguf');

// Streams tokens as they're generated
const stream = client.stream('Write a poem about AI');

stream.on('data', token => process.stdout.write(token));
stream.on('stream:done', ({ tokenCount, elapsed }) => {
  const tps = (tokenCount / elapsed * 1000).toFixed(1);
  console.log(`\n[${tokenCount} tokens · ${tps} t/s]`);
});
const { createClient } = require('v2-llama-ultra');
const client = await createClient();

// OpenAI-compatible chat API
const response = await client.chat.completions.create({
  model:    'llama-3-7b.gguf',
  messages: [
    { role: 'system',  content: 'You are a helpful assistant.' },
    { role: 'user',    content: 'What is 2+2?' },
  ],
  max_tokens: 256,
  stream:     false,
});

console.log(response.choices[0].message.content);

FAQ

Common questions

Does it really work on 4GB RAM?

Yes. With INT4 quantization, LLaMA 7B runs comfortably in ~1.4GB RAM. Even a 13B model fits in 4GB. The chunking engine only keeps 2–3 layers in memory at a time.

What models are supported?

Any model in GGUF format works out of the box (LLaMA 2/3, Mistral, Mixtral, Phi-3, Falcon, etc.). Support for Stable Diffusion and Whisper is on the roadmap.

How do I disable pricing?

Simply set PRICING_ENABLED=false in your .env file, or run llama-ultra config pricing off. All limits are removed instantly. No account or payment needed.

Is it compatible with the OpenAI API?

Yes. The /v1/chat/completions and /v1/completions endpoints are fully compatible. You can point any OpenAI client to http://localhost:3000.

Does inference data leave my machine?

Never. All computation happens locally. LLaMA Ultra doesn't phone home or send telemetry. What happens on your machine stays on your machine.

What's the difference between this and Ollama?

Ollama is great for ease of use. LLaMA Ultra is optimized for constrained hardware. We add intelligent streaming, predictive caching, mixed-precision layers, and hardware-adaptive quantization — features Ollama doesn't have.
